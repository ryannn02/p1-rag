# 协作约定

## 仓库与分支

- 仓库公开，`main` 受保护：合并需 1 人审查通过；管理员豁免，可直接推送（仅限紧急修复）。
- 组员没有写权限，流程是 **fork → 在 fork 上开分支 → 提 PR**，由组长审查合并。
- 分支命名：`feat/xxx`、`fix/xxx`、`data/xxx`、`prompt/xxx`。
- 一人一条分支，不要多人共用同一条。

## 提交与 PR

- 提交信息一句话说清做了什么，别写 `update`、`修改`、`fix bug`。
- PR 描述按 `.github/pull_request_template.md` 四栏填，「如何验证」不能空。
- 涉及接口或数据结构的改动必须在 PR 里写明影响面，并通知全组。
- 改提示词走 `prompt/xxx` 分支，附新旧版本对比结果。

## 接口契约

- 唯一真源是 `src/p1/contracts.py`，**不要在别处再维护一份字段说明**，两份一定会漂移。
- 改契约 = 改这个文件 + 在 PR 说明影响面；禁止在调用处各自拼字典。

## 数据

- 原始语料（PDF / Word / 网页原文）不进仓库，共享方式由组长在组内公布。
- 中间产物（`parsed` / `chunks`）由脚本生成，同样不进仓库；进仓库的是生成脚本。
- 真实咨询记录脱敏后才能进仓库。

约定见 `prompts/README.md`。
