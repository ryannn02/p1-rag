# P1 校园制度问答助手 · 实施方案

- 课题编号：P1（工程应用 / 知识问答 · RAG）
- 团队规模：5 人（本人任核心组长）
- 课程周期：16 周（第 11 周课内完成评测集构建）
- 依据：团队项目实践课题介绍中的 P1 规格（输入输出规格、分档指标、风险预案）

> 说明：本方案只给「步骤 + 工具」，不含具体人员分工。

## 二、各阶段详细步骤

### 阶段 0｜W1 规格冻结与工程骨架

**关键动作**
- 把规格书的输出字段抄成一份「接口契约」，全组按同一份写代码：
  `answer`、`citations[]`（file / page / snippet / score）、`confidence`、`refused`、`refuse_reason`、`suggested_contact`。
- 定目录结构：
  `data/raw`｜`data/parsed`｜`data/chunks`｜`eval/`｜`prompts/`｜`src/`｜`app/`｜`reports/`
- 建仓库并定分支规范：`main` 保护、每人 feature 分支。
- 建立 `prompts/` 目录，提示词进仓库、带版本号、配输入输出样例与回归用例（规格书中的「大模型使用规范」硬性要求）。

**工具**
- Git + GitHub
- `uv` 或 `conda`（锁依赖版本）
- `pydantic`（契约即代码）
- 飞书 / Notion（周报与看板）

**阶段出口**：契约文档落库，仓库可被任一成员克隆跑通空壳程序。

---

### 阶段 1｜W2–W3 制度文档采集

**关键动作**
- 圈定来源：学生手册、教务处、研究生院、学生处、财务处、后勤保卫、信息公开专栏；按「部门 + 年份」建 source 表。
- 网页采集：保存正文 + URL + 抓取时间；PDF/Word 直接下载。
- 文件命名统一：`部门_文件名_年份.pdf`，避免同名覆盖。
- 建立元数据登记表（CSV 或 SQLite）：文件 ID、来源 URL、部门、年份、格式、是否扫描件、页数、处理状态。

**硬指标**：文档 ≥200 份；扫描件占比 ≤20%。达不到就从官网历史通知页补采。

**工具**
- `requests` + `BeautifulSoup`，动态页用 `playwright`
- `trafilatura`（网页正文抽取）
- `pandas`、SQLite（元数据登记）

**阶段出口**：`data/raw` 全量落盘 + 元数据表可查。

---

### 阶段 2｜W3–W4 解析、清洗与切分

**关键动作**
- 文本型 PDF：`PyMuPDF` 抽文本与页码。
- 扫描件：`PaddleOCR`，扫描件多时直接用 `MinerU`（省时，版面还原更好）。
- Word：`python-docx`。
- 清洗：去页眉页脚、去水印、合并断行、统一全半角；保留「第 X 条」等条款编号。
- 切分：优先按标题层级（章 / 节 / 条）切，条款不跨段；超长块用 `RecursiveCharacterTextSplitter` 兜底。
- 每块必须携带 `文件ID + 章节路径 + 页码`——这是引用能点开跳转的唯一依赖。
- 产出固定格式的 `chunks.jsonl`，作为全组唯一数据源。

**工具**
- `PyMuPDF`、`MinerU` / `PaddleOCR`、`python-docx`
- `LangChain TextSplitter`（只用切分器，不引入整套框架）

**阶段出口**：`chunks.jsonl` 字段稳定，抽查 20 块内容与原文件页码一致。

---

### 阶段 3｜W5–W6 检索基线（基础档门槛）

**关键动作**
- 先做单路向量召回：本地嵌入 `bge-m3` 或 `bge-large-zh-v1.5`。
- 向量库选 `FAISS` 或 `Chroma`（200 份文档量级无需 Milvus）。
- 写 20 条问题的冒烟测试，先验证「能召回正确条款」，再谈生成。
- 确定评测口径：Recall@5 命中任一标注来源段落即算命中。

**工具**
- `sentence-transformers`、`FAISS` / `Chroma`、`numpy`
- 实验记录：CSV 起步，需要时再上 `MLflow`

**阶段出口**：端到端可召回的 demo（不含生成）。

---

### 阶段 4｜W7 生成与强制引用

**关键动作**
- 提示词约束：只允许基于给定片段作答，每句论断后挂 `[片段ID]`。
- 模型输出用 JSON Schema 或 Function Calling 强制结构化，不靠模型自觉。
- 后处理校验链路：解析引用 ID → 回查片段是否真实存在 → 不存在则丢弃该句，必要时整条重试一次。
- 记录每次调用的 token 与成本，为终期成本口径做准备。

**工具**
- LLM API（DeepSeek / Qwen / 通义 任一）
- `pydantic` 校验、`instructor` 或原生 function calling
- `tiktoken`（token 计量）

**阶段出口**：回答中每条论断均可回溯到具体片段，「有据可依率」可被脚本统计。

---

### 阶段 5｜W8 拒答机制（本课题最核心训练点）

**关键动作**
- 双闸门设计：先判 top-k 检索分数是否过阈值，再让模型判定「这些片段能否支撑该问题」，两道都过才回答。
- 拒答输出必须含 `refused`、`refuse_reason`（如 `no_evidence_above_threshold`）与建议咨询部门。
- 阈值不拍脑袋：在评测集上扫阈值，画「拒答率 vs 误拒率」曲线选点。

**工具**
- 纯代码实现 + LLM 判定提示词
- `matplotlib` 画阈值曲线

**阶段出口**：不可回答题拒答率可测，误拒率有记录。

---

### 阶段 6｜W9–W11 评测集构建与自动评测

**关键动作**
- 评测集 ≥150 条，四类齐全：可回答、不可回答（≥20 条）、需多跳整合、含歧义。
- 每条标注：`question`、类型、标准来源段落 ID、参考答案要点。
- 来源必须是真实制度文件，禁止使用模型常识题——这是规格书点明的最大风险。
- 标注流程：两人独立标 30 条算一致性；抽 10 条请教师复核。
- 写自动评测脚本，一条命令输出：Recall@5、有据可依率、拒答率、幻觉率、P95 时延。

**工具**
- `Label Studio` 或飞书多维表格（够用即止，不额外搭平台）
- `pytest` 或纯 `argparse` 脚本、`pandas`

**阶段出口**：评测脚本一键可复现，报告数据可直接引用。

---

### 阶段 7｜W11–W13 进阶优化（加分档）

**关键动作**
- 多路召回：BM25 + 向量，用 RRF 融合。
- 接 `bge-reranker-v2-m3` 重排。
- 查询改写：把「缓考最晚啥时候交」这类口语问题改写成可检索表述；信息不足时主动追问。
- 每次改动跑同一份评测脚本，结果写入对比表；提示词改动同步更新回归用例。

**工具**
- `rank_bm25` 或 Elasticsearch
- `bge-reranker-v2-m3`
- LLM 改写提示词 + 回归用例集

**阶段出口**：方法对比表（各方法的 Recall@5 / 拒答率 / 时延 / 成本）。

---

### 阶段 8｜W13–W15 界面与 API

**关键动作**
- Web 界面：能提问、能展开引用、能跳转原文高亮即可。
- JSON API：`FastAPI` + `pydantic` 模型，字段与阶段 0 契约完全一致。
- 时延优化：嵌入与重排批量化、高频问题缓存、流式输出。
- 指标：P95 ≤ 8s（进阶档 ≤ 5s）。

**工具**
- `Streamlit` 或 `Gradio`（不写 React，把时间留给 RAG）
- `FastAPI` + `uvicorn`
- `diskcache` 或 Redis（缓存）

**阶段出口**：给不懂技术的同学试用，能独立完成一次「提问 → 看引用 → 核对原文」。

---

### 阶段 9｜W15–W16 报告与交付

**关键动作**
- 评测报告（Markdown + 图表）。
- badcase 归因表：每类错误对应到具体系统层改动（检索 / 切分 / 提示词 / 阈值）。
- 大模型成本口径：调用次数 / token 或金额 / 单次任务成本，并说明优化措施（规格书硬性要求）。
- 一键复现脚本：从原始数据到评测结果；README 写清运行方式。
- Git tag 打版本，冻结交付快照。

**工具**
- `matplotlib` / `plotly`
- `Makefile` 或 `invoke`（一键入口）

**阶段出口**：交付物齐备，助教/教师按 README 可复现结果。

```json
{
  "question": "缓考申请最晚什么时候交？",
  "answer": "……（每句论断后附 [片段ID]）",
  "citations": [
    {
      "file": "教务处_缓考管理办法_2023.pdf",
      "page": 3,
      "section": "第三章 第十条",

    }
  ],
  "confidence": 0.82,
  "refused": false,
  "refuse_reason": null,
  "suggested_contact": null
}
```

## 四、指标对照表

| 指标 | 基础档（必须达成） | 进阶档（加分项） |
| --- | --- | --- |
| 检索 Recall@5 | ≥ 0.75 | ≥ 0.90 |
| 答案有据可依率 | ≥ 0.80 | ≥ 0.92 |
| 不可回答题拒答率 | ≥ 0.50 | ≥ 0.80 |
| 人工评测幻觉率 | ≤ 15% | ≤ 8% |
| P95 响应时延 | ≤ 8 s | ≤ 5 s |
| 数据规模 | 单路向量召回 + 引用展示 + 100 条评测集 | 混合召回 + 重排 + 查询改写 + 阈值调优 + 评测自动化 |

## 六、硬卡点与风险

- 阶段 3 结束必须跑通端到端：基础档要求「单路向量召回 + 引用展示 + 100 条评测集」。
- 阶段 5 的拒答做不好，后面所有指标都会被幻觉率拖垮，值得多投时间。
- 「评测集自己造自己答」是最大风险：评测集必须来自真实制度文件，且需教师抽查复核。
- 规格书建议 P1 配置 3—4 人，本组 5 人，多出的人力优先压在文档解析清洗与评测集标注这两块纯工时瓶颈上。
- 提示词改动必须留痕：进仓库、带版本、配回归用例，否则指标会莫名其妙漂移。
