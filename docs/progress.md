### 阶段 3｜检索基线

| 指标 | 结果 |
| --- | --- |
| 向量模型 | `BAAI/bge-small-zh-v1.5`（512 维，本地跑，无需 API） |
| 索引 | **4583 条 × 512 维**，`data/index/embeddings.npy` 9.4 MB，M 系列芯片约 1 分钟建完 |
| 冒烟集 | `eval/smoke_questions.jsonl` 20 条，每题标注期望制度 + 期望事实，逐条人工核对过 `doc_id` |
| **Recall@5** | **19/20 = 95%**（同文件限席 2）；不限席为 85%，限席 1 为 100% |
| Top-1 命中 | 13/20 = 65% |
| 单查询耗时 | 约 15 ms（暴力余弦） |
| 端到端 | 可召回 demo 已通（阶段 3 不含生成） |

**Recall@5 口径**：top-5 里任一 chunk 的 `doc_id` 命中标注的制度文件即算命中。标注到制度级
不标到段落——同一事实在长篇制度里可能落在相邻条款。明细进 `reports/retrieval_smoke.csv`。

**没上 FAISS / Chroma**：4583 条语料的暴力余弦单查询 15 ms，索引 9.4 MB，公式只有一行。
多引一个向量库只是多一份要同步的状态、多一套要解释的构建流程。语料上到十万级再换
（`src/p1/retriever.py` 里留了 `ponytail:` 标注写明升级路径）。

**「同文件限席」是阶段 3 最关键的参数**：`教学管理文件汇编`（300 页）、`学生手册（2023版）`、
`留学生规章制度` 这三份汇编把同一批制度原文又收了一遍，向量几乎一样，不干预时 top-5 会被
它们整片占满，独立制度文件被挤出去。限制同一份文件最多占 2 席后 Recall@5 从 85% 升到 95%、
Top-1 从 55% 升到 65%。默认取 2 而不是 1：20 条问题定不下这个参数，限 1 会让「一个制度用
两条相邻条款回答」的场景被硬塞进无关文件，这个值留给阶段 6 的 ≥150 条评测集定。

### 阶段 4｜生成与强制引用

**核心设计：引用元数据全部由代码回填，不由模型生成。** 模型只能从召回结果里挑编号
（输出 `used: [1,3]`），`file / page / section / score` 一律由 `src/p1/generator.py`
从检索结果取。「编造引用」这个失败模式因此在结构上不可能发生，不靠提示词自律。

| 项目 | 结果 |
| --- | --- |
| 提示词 | `prompts/answer/v2.md`（v1 保留），6 条回归用例在 `prompts/answer/cases.jsonl` |
| 端到端入口 | `python -m scripts.ask "图书馆一次能借几本书"`（命令行） |
| 演示界面 | `python -m scripts.serve` → http://127.0.0.1:8000（网页） |
| 用例验收 | **6/6 通过**（含 2 条拒答题），明细 `reports/answer_eval.csv` |
| 单元测试 | `test_generator.py` 13 条 + `test_prompts.py` 13 条 + `test_serve.py` 3 条 = **29 passed**，stub 模型，不联网不烧 token |
| 模型接入 | DeepSeek `deepseek-chat`，走 OpenAI 兼容 `/chat/completions`，复用已有的 `requests`，不为每家厂加一个 SDK |
| 单次问答耗时 | 约 0.8 秒（检索 15 ms + 模型调用）；首次提问含本地向量模型加载约 15 秒 |

**「引用不成立就不作答」这条底线**：模型给不出可核对的编号、输出不是合法 JSON、
或召回为空，一律转拒答并给出归口部门。**没有依据就拒答属于阶段 5**，阶段 4 只做到
这一步为止。

**跨副本去重**：同一条款常同时在汇编（`学生手册（2023版）`、`教学管理文件汇编`）和独立制度
里各存一份，正文只差条号、列表序号、标点和换行。判重键把这几样全剥掉再比对，重复的只留
分数高的那条，并把答案里指向被合并条款的标号一并过去，免得引用列表出现重复条款或留下
悬空编号。**数字不剥**：`外借 30 册` 与 `外借 10 册` 是两条不同条款，抹掉数字会让引用指错数。

全语料核对：4583 个 chunk 归成 4135 组，821 个 chunk 落在 373 个多副本组里，组内文本长度
差异全部小于 25%，逐组抽样核对均为真副本（汇编与独立制度各一份），无误并。

**演示界面（阶段 8 的提前版）**：`python -m scripts.serve` 起一个本地页面，输入问题即出答案与
引用卡片（文件名 / 章节 / 页码 / 匹配度）。只用标准库 `http.server`——为一个演示页面引 Web 框架
不划算；真要产品化（多用户、流式输出、鉴权）时再换。只在 `127.0.0.1` 监听，不暴露到局域网；
入参在 `parse_question()` 里挡掉非 JSON、空问题和超过 200 字的输入，模型报错返回 502 而不把
服务打挂。测试 3 条（不启服务、不联网）。

**v2 相对 v1 的改动**：v1 下「留学生申请奖学金需要什么条件」被模型拿中国籍学生的奖学金
条款硬答（原文明确写「具有中华人民共和国国籍」）。v2 增加一条规则——引用前先核对条款的
适用主体，主体不符按无依据拒答。该题因此从硬答改为正确拒答（`学生处（学生资助管理中心）`）。
按约定改提示词新建 `vN+1.md`，`v1.md` 保留。

### chunk 字段

```json
{
  "chunk_id": "8beaca14b3b6-00000",
  "doc_id": "8beaca14b3b6",
  "dept": "教务处",
  "title": "教学管理文件汇编",
  "year": "2021",
  "section": "第一篇 教育部文件",
  "page": 1,
  "text": "……",
  "chars": 760,
  "source_url": "https://jwc.sspu.edu.cn/_upload/article/files/..."
}
```

`section` 与 `page` 是引用展示的关键：阶段 4 生成答案时，每句论断要能回到具体的章节与页码。

### 重建方式

```bash
python -m scripts.build_corpus     # data/raw → data/parsed + data/chunks.jsonl
python -m scripts.stats            # 语料验收口径统计
python -m scripts.build_index      # data/chunks.jsonl → data/index/（换模型或换语料都要重建）
python -m scripts.retrieval_smoke  # 20 条冒烟，出 Recall@5
python -m scripts.eval_answer      # 6 条端到端问答打真模型，核对引用与拒答
```

组员克隆仓库后，只要从共享位置同步 `data/raw`，跑一条命令即可重建全部中间产物；仓库大小维持在几 MB。

## 七、过程中解决的主要问题

1. **`FIELDS` 读整个 CSV 而非表头**：登记表一有数据，字段名就被污染成 `fetched_at\n8beaca14b3b6`，所有写入抛 `ValueError`。首次试采时表为空所以没暴露，属最隐蔽的一个。
2. **文种判定用「包含」过宽**：把「关于网报信息不符合规定的重要提醒」当成制度收进来。改为去掉尾部括号后必须以文种词结尾，误收从 16 条降到 0。
3. **正文藏在 JS PDF 播放器里**：信息公开站 21 个条目只存到 80–145 字的空壳，因为正文是 `pdfsrc=` 内嵌 PDF 而非 `<a>` 附件。补上该来源后救回《学生手册（2023版）》《章程（2023年修订版）》等关键文本。
4. **python-docx 读不到文本框**：有制度整篇塞在文本框里，只提取到 15 字。改为直接扫 `document.xml` 兜底。
5. **同栏目两个 URL**：保卫处、后勤保障处同一栏目存在 `/<id>/list.htm` 与 `/_s3/<id>/list.psp` 两份，会重复采集；按制度名批次内去重 + 跨站去重解决。
6. **HTML 碎行**：`<span>` 拆行导致「根据 / 《财政部 / 教育部」各占一行，影响可读性与检索；合并短行后又把 5 个超长块（最长 1510 字）按句号切回 800 字以内。
7. **`.doc` 无解析库**：改用 macOS 自带 `textutil`，零新增依赖；Linux 上需换 LibreOffice。
8. **去重键按部门分桶，跨部门重复漏网**：原键是 `(dept, base_title)`，同一份制度从研究生处站和信息公开站各采一次会两份都留下；`base_title` 也没剥标题前置日期，研究生处站点的 `2024-03-01上海第二工业大学…` 与 `上海第二工业大学…` 被判成两个名字。改为跨部门按归一化标题归并、保留版本较新的一份（同年份时部门站优先），剔掉 8 份。其中《硕士学位授予办法》原留的是研究生处 2018 版、**现行版本其实在信息公开（2022 年修订）**——不去重会让阶段 4 的引用指向过期版本。
9. **两套收录口径分裂**：人工整理件允许「规划／年度工作要点／工作方案／规范」结尾，自动采集器不允许（否则「XX工作实施方案」的通知会被一起收进来）。结果 triage 用采集口径回头把人工导入的 12 份当「非制度条目」重新排除了。已把 `MANUAL_WORDS` 收进 `scripts/probe.py`，triage 与 import_manual 共用一套，不再各写一份。
10. **汇编类长文档霸榜**：见阶段 3 一节，用「同文件限席」解决。
11. **答案标号被自己删掉**：`renumber()` 先把答案里的旧编号换成占位符再还原成新编号，最后一行才删「模型编造的悬空编号」——顺序反了，刚还原出来的新标号一起被删光。端到端表现为答案末尾的 `[1]` 凭空消失、与引用列表对不上。改成先把悬空编号删掉再还原占位符。
12. **跨副本去重的别名映射错位**：`dedupe_citations()` 把「被合并条款 → 保留条款」的映射记成了保留条款在结果列表里的**下标**，而 `renumber()` 查的是**原始编号**，两边对不上，重复标号变成悬空引用被删。改记原始编号；合并后指向同一条的重复标号再收敛成一个。
13. **提示词缺主体核对**：见阶段 4 一节，`v2.md` 补上「条款写明的适用主体与提问对象不符时按无依据拒答」。
14. **判重键不够狠，同一条款被引三次**：转专业条件在汇编、学生手册、独立办法里各有一份，三份只差条号（`第一条`／`第三条`）、列表序号（`1．`／`1.`／无）、标点和换行。原判重键只剥条号与空白，三份各自成组，同一个问题回上来三条一模一样的引用。补上列表序号与标点的剥离后合并成一条，全语料无误并。
15. **`base_title` 漏剥校名前缀**：补采校长办公室栏目时发现《上海第二工业大学校门出入管理规定》与《校门出入管理规定》、《上海第二工业大学校园治安管理规定》与《校园治安管理规定》被当成四份。补上校名前缀剥离后归并成两组，保留 2023 新版、丢弃 2011 旧版。

- **仍有 1 条 top-1 无法命中汇编**：q19（学生处分原则）在限席 2 下被 `教学管理文件汇编` 与 `留学生规章制度` 挤掉，但期望文件仍在 Recall@5 内，不阻断阶段 4。

## 九、下一步

进入阶段 5：兜底与拒答。阶段 4 只做到「引用不成立就不作答」，阶段 5 要处理检索召回了内容
但确实答不上来的情形——置信度低于阈值、条款只沾边不覆盖提问主体、问题超出制度范围。这一步
要把拒答原因分类（无相关制度／有制度但未覆盖该主体／问题不属于制度范畴）、每类给出对应的
归口部门，并保证拒答话术统一，不出现「模型自由发挥式道歉」。

不依赖新数据；但要在阶段 6 的 ≥150 条评测集上验证拒答的**误拒率**，那是阶段 4/5 唯一的真正风险。
