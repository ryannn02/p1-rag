## 1. 引言

### 1.1 编写目的

明确 P1「校园制度问答助手」要交付什么、达到什么标准、按什么口径验收，作为小组开发、评测与结项的共同依据。本文档同时是需求追踪矩阵的载体：每条需求都要能对应到验收口径与实现状态。

### 1.2 项目背景

学校现行制度分散在学生手册、教务处、研究生处、学生处、财务处、保卫处、后勤保障处等十余个部门的网站上，格式包含网页、PDF、Word，同一制度常有多个年份版本。学生与辅导员在办理跨部门事务时，需要人工翻找多份文件才能得到一个可依赖的答复；答复一旦出错，责任落在答复人身上。

本课题要求做一套面向全校师生的制度问答系统，训练重点不是「搭一个聊天机器人」，而是**把模糊的口语提问变成有据可依、无据可拒的可靠回答**。模糊提问改写、强制引用、不可回答拒答是三条主线。

### 1.3 术语表

| 术语 | 含义 |
| --- | --- |
| RAG | 检索增强生成：先检索相关文档片段，再让大模型基于片段作答 |
| chunk | 切分后的最小检索单元。本项目按「章 / 节 / 条」切分 |
| 引用（citation） | 回答中每条论断绑定的来源：文件、页码 / 章节、原文片段、匹配得分 |
| 强制引用 | 每句论断必须绑定来源片段，绑定不上就不输出该句 |
| 拒答 | 语料无相应依据时明确声明「未涵盖」，而不是编造答案 |
| Recall@5 | 检索前 5 条结果中命中标注来源的比例 |
| 有据可依率 | 回答中能回溯到有效引用片段的论断占比 |
| 幻觉率 | 人工评测中「回答内容无来源支撑」的比例 |
| 多跳整合 | 需要跨多份文件整合才能回答的问题（如休学 + 宿舍 + 学费联动） |

## 2. 项目概述

### 2.1 建设目标

面向全校师生提供制度问答服务：用户用口语提问，系统给出**带原文引用的答复**；语料中查不到依据时，**明确拒答并告知咨询渠道**。

### 2.2 系统边界

| 范围内 | 范围外 |
| --- | --- |
| 校内现行有效的规章制度问答 | 国家法律、地方法规的一般性问答（可作为上位法随制度采集，但不作为主要知识范围） |
| 依据检索结果作答，并给出原文引用 | 替用户办理业务、代替审批 |
| 语料无依据时拒答并给出咨询渠道 | 提供法律意见或承诺办理结果 |
| 面向校内公开制度文档 | 需要登录或属于个人信息的内容 |

### 2.3 用户与干系人

| 角色 | 特征与诉求 | 关键场景 |
| --- | --- | --- |
| 在校学生（本专科 / 研究生） | 提问口语化、缺主体、不知道自己该查哪份文件；入学季咨询量集中 | 缓考怎么申请、学分怎么算、奖学金怎么评、被处分能否申诉 |
| 辅导员 / 教务老师 / 研究生秘书 | 需快速给出准确答复，答复错误要担责；关心引用是否可核对 | 学生提问后，一分钟内拿到答案 + 三条最相关条款 |
| 制度归口部门 | 希望重复咨询被系统分流，同时不希望系统给出与正式文件不一致的答复 | 制度更新后系统同步 |
| 项目组与授课教师 | 关注工程完整度、指标是否达标、过程是否可复现 | 结项评审、一键复现 |

### 2.4 与课题规格书的对应

本课题规格书（《团队项目实践课题介绍》P1 章节）给出的输入输出规格、分档指标与风险预案，是本文档各项指标的来源；本文档在其基础上补充了用户角色、用例流程、接口细节与验收方法。

## 3. 功能需求

需求编号规则：FR-XX。优先级采用 MoSCoW：**必须**（基础档必须达成）、**应该**（进阶档加分）、**可选**。

### 3.1 语料采集与治理

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-01 | 系统应能从学校公开网站采集制度文档（网页、PDF、Word），并登记来源 URL、部门、年份、格式 | 必须 |
| FR-02 | 采集应去重：同一 URL 不重复入库；同一制度多版本只保留现行有效版本 | 必须 |
| FR-03 | 采集应过滤非制度内容（公示、名单、招生信息、新闻通知、申请表与流程图） | 必须 |
| FR-04 | 采集应支持断点续采与礼貌抓取（单线程、间隔、失败重试），不对学校服务器造成压力 | 必须 |
| FR-05 | 语料应为可复算的登记表 + 可重跑脚本，原始文件不进版本库 | 必须 |
| FR-06 | 语料应满足规模要求：制度文档 ≥200 份，扫描件占比 ≤20% | 必须 |

### 3.2 文档解析与切分

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-07 | 系统应支持 PDF、Word（.doc/.docx）、HTML 三类来源的正文提取 | 必须 |
| FR-08 | 解析应清洗页眉页脚、水印、导航与版权信息等噪声 | 必须 |
| FR-09 | 切分应优先按「章 / 节 / 条」进行，条款不跨块；超长条款按句切分，单块不超过 800 字 | 必须 |
| FR-10 | 每个切分单元应携带可回溯定位信息：来源文件、页码 / 章节路径 | 必须 |
| FR-11 | 解析失败的文档应记录原因并可复核，不允许静默丢弃 | 必须 |

### 3.3 检索

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-12 | 系统应基于用户提问检索出最相关的制度片段，返回前 k 条及得分 | 必须 |
| FR-13 | 检索结果应覆盖多份文件（跨部门制度交叉查询场景） | 必须 |
| FR-14 | 系统应支持口语提问的查询改写：补全省略主体、把口语表述换成制度用语 | 应该 |
| FR-15 | 系统应在多路召回（关键词 + 向量）基础上做重排 | 应该 |
| FR-16 | 系统应在信息不足时主动追问，而不是猜测 | 可选 |

### 3.4 生成与引用

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-17 | 回答必须基于检索到的片段生成，不得引入语料外信息 | 必须 |
| FR-18 | 每条论断必须绑定来源片段；无法绑定的论断不得输出 | 必须 |
| FR-19 | 每个引用应可展开查看：文件名、页码 / 章节、原文片段、匹配得分 | 必须 |
| FR-20 | 引用应支持跳转原文（Web 界面可点开核对） | 应该 |
| FR-21 | 回答应为结构化输出，字段固定，可被程序消费 | 必须 |

### 3.5 拒答

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-22 | 语料中无依据时，系统必须明确拒答，不得编造 | 必须 |
| FR-23 | 拒答应给出原因（如检索得分未达阈值）与建议咨询渠道 | 必须 |
| FR-24 | 拒答判定应采用双重闸门：检索得分阈值 + 模型对「片段能否支撑该问题」的判定 | 应该 |
| FR-25 | 拒答阈值应通过评测集调优，而非人工拍定 | 应该 |

### 3.6 界面与服务接口

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-26 | 提供 Web 问答界面，可提问、可展开引用、可核对原文 | 必须 |
| FR-27 | 提供 JSON API，字段与接口契约一致 | 必须 |
| FR-28 | 界面应支持流式输出，避免长时间无反馈 | 应该 |

### 3.7 评测与报告

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-29 | 建立评测集 ≥150 条，覆盖可回答、不可回答（≥20 条）、多跳整合、含歧义四类，并标注来源段落 | 必须 |
| FR-30 | 评测集必须来自真实制度文件，不得使用模型常识可答的问题 | 必须 |
| FR-31 | 提供一键评测脚本，输出 Recall@5、有据可依率、拒答率、幻觉率、响应时延 | 必须 |
| FR-32 | 提供 badcase 归因表：每类错误对应到具体系统层改动（检索 / 切分 / 提示词 / 阈值） | 必须 |
| FR-33 | 提供大模型调用成本口径：调用次数、token 或金额、单次任务成本及优化措施 | 必须 |

## 4. 非功能需求

| 编号 | 类别 | 需求 |
| --- | --- | --- |
| NFR-01 | 性能 | P95 响应时延基础档 ≤8 秒，进阶档 ≤5 秒 |
| NFR-02 | 可靠性 | 检索或生成失败时给出明确错误提示，不返回空白或半成品答案 |
| NFR-03 | 可复现 | 从原始数据到评测结果可一键复现；评测脚本与语料登记表进版本库 |
| NFR-04 | 可维护 | 提示词进仓库、带版本号、配输入输出样例与回归用例；改提示词需留痕 |
| NFR-05 | 结构化 | 凡是需要被程序消费的模型输出，必须用 JSON Schema 或 Function Calling 约束 |
| NFR-06 | 成本 | 单次问答成本可核算；嵌入与重排批量化、高频问题缓存 |
| NFR-07 | 合规 | 只采集公开制度文档；不采集需登录内容；真实咨询记录脱敏后才能使用 |
| NFR-08 | 可移植 | 仅 `.doc` 解析需要系统工具：macOS 用自带 `textutil`，Windows / Linux 用 LibreOffice 的 `soffice`，两者皆无则跳过该格式；其余全部跨平台 |
| NFR-09 | 安全 | API Key 等凭据不入库，统一走环境变量 |

## 6. 接口需求

### 6.1 回答接口契约

```json
{
  "question": "缓考申请最晚什么时候交？",
  "answer": "……（每句论断后附 [片段ID]）",
  "citations": [
    {
      "file": "教务处_缓考管理办法_2023.pdf",
      "page": 3,
      "section": "第三章 第十条",
      "snippet": "……原文片段……",
      "score": 0.87
    }
  ],
  "confidence": 0.82,
  "refused": false,
  "refuse_reason": null,
  "suggested_contact": null
}
```

### 6.2 拒答输出契约

```json
{
  "question": "留学生能申请学业奖学金吗？",
  "refused": true,
  "answer": "在已收录的 263 份现行制度文件中，未找到留学生申请资格的相关规定，无法给出可靠答复。建议咨询研究生院奖助办公室。",
  "refuse_reason": "no_evidence_above_threshold",
  "top_retrieval_score": 0.28,
  "suggested_contact": "研究生院奖助办公室"
}
```

### 6.3 检索单元字段

`chunk_id`、`doc_id`、`dept`、`title`、`year`、`section`、`page`、`text`、`chars`、`source_url`。其中 `section` 与 `page` 是引用可跳转原文的前提。

## 7. 关键用例

### UC-01 新生高频咨询分流

- 参与者：大一 / 研一新生
- 前置条件：语料已入库并建立索引
- 主流程：学生问「缓考怎么申请、最晚什么时候交」→ 系统改写为可检索表述 → 检索学生手册与教务文件 → 返回答案并附条款原文 → 学生点开核对
- 异常流程：语料未涉及 → 拒答 + 建议咨询教务处考务办公室
- 价值：把重复咨询从辅导员身上卸下来

### UC-02 辅导员 / 教务老师快速答复

- 参与者：辅导员、教务秘书
- 主流程：输入学生问题 → 系统返回答案 + 三条最相关条款 → 老师据此回复学生
- 特殊要求：引用必须可核对，因为答复错误要担责
- 价值：逼学生认真对待引用与拒答，而不是做聊天玩具

### UC-03 跨部门制度交叉查询

- 参与者：办理跨部门事务的学生
- 主流程：问「休学后宿舍和学费怎么处理」→ 系统跨多份文件整合 → 返回分点答复并分别标注来源
- 特殊要求：多跳整合，检索必须覆盖多份文件
- 价值：多文档整合是 RAG 的真正难点，也是最容易拉开小组差距的地方

### UC-04 无依据拒答

- 参与者：任意用户
- 主流程：提问 → 检索得分低于阈值 → 系统判定片段不足以支撑 → 拒答并说明「已收录 N 份文件中未涵盖」+ 建议咨询渠道
- 价值：**这是本课题最重要的一类输出**，直接决定系统能否被信任

## 8. 验收标准

| 指标 | 基础档（必须达成） | 进阶档（加分项） | 现状 |
| --- | --- | --- | --- |
| 检索 Recall@5 | ≥ 0.75 | ≥ 0.90 | **0.95**（19/20，阶段 3） |
| 答案有据可依率 | ≥ 0.80 | ≥ 0.92 | 阶段 4 做到结构上不可编造（引用只由代码回填），6 条用例 6/6；比率待阶段 6 测 |
| 不可回答题拒答率 | ≥ 0.50 | ≥ 0.80 | 2 条不可回答用例全拒答；比率待阶段 6 测 |

| P95 响应时延 | ≤ 8 s | ≤ 5 s | 未测（阶段 8） |

| 交付物 | 可运行系统 + 评测报告 + 可复现脚本 | 追加 badcase 归因表 + 成本口径 + 进阶指标 | 采集与解析流水线已就绪 |

## 10. 约束与假设

| 类型 | 内容 |
| --- | --- |
| 时间约束 | 课程 16 周，第 11 周课内完成评测集构建 |
| 人力约束 | 课题建议 3—4 人，实际 5 人；多出的人力应压在文档解析清洗与评测集标注两块纯工时瓶颈上 |
| 数据约束 | 无真实咨询记录，评测集需由组内自拟并注明分布偏差 |
| 技术约束 | 不引入不必要的重装备：200 份文档量级用本地向量库即可，不需要集群方案；站点均为服务端渲染，暂不需要浏览器自动化 |
| 网络约束 | 学校站点直连可达；GitHub 需走代理；包源使用国内镜像 |
| 版权约束 | 只使用学校公开制度文档，原始文件不在公网仓库分发 |

## 11. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 评测集自己造自己答 | 指标虚高，与真实可用性脱节 | 评测集必须来自真实制度文件；抽查 10 条由教师复核 |
| 只用模型常识题测试 | 检索与拒答能力测不出来 | 评测集强制包含 ≥20 条不可回答题与多跳题 |
| 幻觉无法归因 | 改了不知道改得对不对 | 提交 badcase 归因表，每类错误对应系统层改动 |
| 提示词随意改动 | 指标漂移且无法回滚 | 提示词进仓库、带版本号、新旧版本对比后才切换 |
| 语料过时 | 给出已废止条款 | 登记表 `status` 区分 `effective` / `archived` / `excluded`，检索只用现行有效 |
